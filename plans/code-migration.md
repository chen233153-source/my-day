### הניתוב


`go(view)` עושה שלושה דברים: מחליף `.hide` על חמש ה-`<section>` שכבר קיימות ב-`index.html`,
מסמן את הטאב הפעיל לפי `data-go`, וקורא ל-`render()`.
`render()` הוא if/else של חמישה ענפים שקורא ל-`renderNow` / `renderHabits` / `renderGratitude` / `renderCompass` / `renderAdvisor`.

**מה שלא נמצא ב-`VIEWS` בכלל:** תקועה, רגיעה, ספירה לאחור, בלוק, נשימה, חגיגה, אונבורדינג.
הם חיים בשתי שכבות מעל הראוטר:

- `openSheet(html)` / `closeSheet()`: גיליון תחתון עם scrim
- `openFull(html, cleanup)` / `closeFull()`: מסך מלא, עם `fullCleanup` שמנקה טיימרים

זו הסיבה שהראוטר נראה קטן מהאפליקציה בפועל.

### מערכת המצבים במסך `now`

```js
function phase() {
  const d = today();
  const hour = new Date().getHours();
  if (!d.big3) return 'morning';          // עוד לא נשמרו משימות
  if (d.evening) return 'done';           // סקירת הערב נשמרה
  const allDone = d.big3.length > 0 && d.big3.every(t => t.done);
  if (hour >= S.settings.eveningHour || allDone) return 'evening';
  return 'day';
}
```

- `nowMorning`: תודה אחת, שלוש משימות, בורר מטרה שמופיע רק אחרי שנכתבה משימה, כפתור שמירה
- `nowDay`: המשימה הבאה שלא בוצעה, משגר 5-4-3-2-1, "עשיתי", "תקועה"
- `nowEvening`: אבן הקסם, המשימה של מחר, "סימנת X מתוך Y", כפתור סגירה
- `nowDone`: תצוגה בלבד, עם אפשרות לפתוח מחדש את היום

שלושת המצבים הראשונים מסתיימים ב-`tilesHTML()`: שלוש אריחים, רגיעה / תודה / תקועה.

### `addVote()`

```js
function addVote(goalId) {
  S.votes++;
  if (goalId) {
    const g = S.goals.find(x => x.id === goalId);
    if (g) g.votes = (g.votes || 0) + 1;
  }
  save();
}
```

מחובר לשתי נקודות בלבד:

1. `completeTask()`: סימון משימה של היום, מעביר את `goalId` של המשימה
2. סימון הרגל ב-`renderHabits`: קורא `addVote()` בלי מטרה. ביטול הסימון עושה `S.votes = Math.max(0, S.votes - 1)`

כלומר: **הקול היום נספר למונה גלובלי ולמטרה, אף פעם לא לזהות.**
הזהות היא מחרוזת נפרדת ב-`S.identity`, והקשר היחיד ביניהן הוא כיתוב התצוגה
`קולות לאישה שאת בונה` ב-`headerHTML()`. אין קשר במודל הנתונים.

### מה בקוד הקיים טוב יותר ממה שהעיצוב מניח, וחייב לשרוד

זו הרשימה שהכי חשוב לא לאבד בהגירה.

1. **`habitState()` וה-`born` guard.** הרגל לא "מפספס" ימים שקדמו ליצירתו:
   `const born = h.created || Object.keys(h.log).sort()[0] || t;`
   בלי זה הרגל חדש נפתח בהאשמה. זו בדיוק הפילוסופיה של המפרט, כבר ממומשת.

   בלי הדפוס הזה כל ספירה לאחור שנסגרת באמצע משאירה `setInterval` דולף. המפרט מתאר עשרה מסכי טיימר נוספים, וכולם צריכים את זה.
3. **`content` של `knowledge.js` כבר מכסה את מפרט רגיעה.** `STATES` הם בדיוק שלושת המצבים של דב דנה,
   `TOOLS` נגזרים מהמצב ולא מתפריט אחיד (הדרישה המרכזית ב-`calm-flow.md`), `SCALE` הוא 22 המדרגות,
   ומחרוזת ה-`prefix` של `defusion` היא מילה במילה השורה ש-`voice.md` אוסר לגעת בה.
   **אין צורך לכתוב את התוכן הזה מחדש. צריך רק להעביר אותו ממסכי גיליון למסכי מסלול.**
4. **פרטי מובייל שקל לאבד:** `font-size: 16px` בשדות (מונע זום בספארי), `env(safe-area-inset-*)`,
   `overscroll-behavior-y: none`, `@media (prefers-reduced-motion: reduce)`, `-webkit-tap-highlight-color: transparent`.
   `habit-flow.css` לא מטפל באף אחד מהם, כי הוא נכתב למסגרת 390x844 על לוח עיצוב.
5. **`esc()` על כל ערך שמגיע מהמשתמשת.** האפליקציה בונה HTML ממחרוזות, וזה הדבר היחיד שמונע ממנה להישבר על גרש.
6. **ייצוא JSON שמנקה את מפתח ה-API.** משתמשת אחת, בלי שרת, בלי גיבוי. זה הגיבוי היחיד שקיים.
7. **`visibilitychange` שמזהה חצות** ומחזיר למסך `now` ביום חדש.
8. **`load()` שממזג לתוך `DEFAULTS`.** זה מה שיאפשר את הגירת הנתונים בהמשך בלי לאבד מידע.

### 2.2 עמוד השדרה: זהות וקולות

זה הפער העמוק ביותר, ולא רק בגלל הקוד.

**מה יש:** `S.identity` הוא מחרוזת. `S.votes` הוא מספר גלובלי אחד.

**מה נדרש, לפי מה שבאמת כתוב במסכים:**

הזהות מופיעה בשישה מקומות, בארבעה תפקידים שונים:

### 4.3 מה קורה למשתמשת שכבר יש לה נתונים

יש משתמשת אחת, חן, עם נתונים אמיתיים. ההגירה חייבת להיות אוטומטית וחד-פעמית.

הכלי כבר קיים: `load()` ממזג לתוך `DEFAULTS`. מוסיפים לו שלב.

```
KEY נשאר 'my-day-v1'. מוסיפים S.schema = 2.
בטעינה, אם !S.schema, מריצים migrate1to2(S) פעם אחת ושומרים.
לפני שכותבים, שומרים עותק של הישן תחת 'my-day-v1-backup-pre-v2'.
```

מה `migrate1to2` עושה, בשמות:

1. **`identity`**: מסירים את הקידומת `אני אישה ש` או `אני אדם ש` ושומרים את השארית כ-`predicate`
   ברשומה אחת עם `scope: 'primary'`. `createdAt` מקבל את זמן ההגירה.
   זהויות ההרגל והמטרות נוצרות ריקות ויורשות מהראשית עד שנכתבות
2. **`votes` → `voteLog`**: כאן יש אובדן אמיתי. המונה הגלובלי לא יודע באיזה יום ניתן כל קול.
   מה שכן ניתן לשחזר: כל `habits[].log[day]` הוא קול עם תאריך, וכל `days[k].big3[].done === true` הוא קול עם תאריך.
   **מייצרים את `voteLog` מהמקורות האלה, ולא מהמונה.**
   אם הסכום שיוצא קטן מ-`S.votes`, שומרים את ההפרש כרשומה אחת
   `{source: 'legacy', day: תאריך ההגירה, count: ההפרש}` כדי שהמספר בכותרת לא יקטן פתאום.
   **זה החלק היחיד בהגירה שאי אפשר לעשות מושלם.**
3. **`days[k].big3` → `tasks`**: משימות של היום ומחר עוברות עם `when: 'today'`.
   משימות מימים קודמים שלא סומנו **לא עוברות**. `tasks-flow.md` אוסר העברה אוטומטית של מה שלא נעשה.
   משימות שסומנו לא עוברות בכלל, כי אין ארכיון
4. **`habits`**: אם יש יותר מהרגל אחד, **לא מוחקים אף אחד.**
   הראשון (הוותיק ביותר לפי `created`) מסומן `active: true`, השאר `active: false` ונשארים בהיסטוריה.
   המסך מציג את הפעיל. **אסור למחוק נתונים בהגירה.**
   הודעה חד-פעמית: "עברנו להרגל אחד בכל פעם. השאר שמורים."
5. **`goals[].tactics`**: כל טקטיקה הופכת ל-`{text, target: 1, done: [], trigger: ''}`
6. **`goals[].why`**: מחרוזת הופכת למערך באורך 1
7. **`gratitude`**: כל רשומה עם `type: 'glimmer'` מועברת ל-`glimmers` ויורדת מ-`gratitude`
8. **`days[k].gratitudeToday`**: נמחק רק אם הטקסט שלו כבר קיים ב-`gratitude[]`. אחרת מועבר

**מה נשאר מיותם:** `S.weekly[].pct` נשאר במערך ולא מוצג. `S.feelings` נשאר ולא מוצג.
`S.vision` נשאר ולא מוצג. שלושתם לא מזיקים ולא עולים כלום, ומחיקה שלהם היא אובדן שאין לו החזר.

**בדיקת ההגירה:** לוקחים את קובץ הייצוא של חן, מריצים `migrate1to2` עליו בבידוד,
ומוודאים שלושה דברים: המספר בכותרת הקולות לא קטן, אף הרגל לא נעלם, אף תודה לא נעלמה.
